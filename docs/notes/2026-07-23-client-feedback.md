## Scope: bugs

- **B1 — Mobile: menu button overlaps the logo** (Sammy's screenshot;
  also the client's issue 6). Header layout collision at mobile
  widths.
- **B2 — Mobile: dark-mode text contrast on first load.** First visit
  on mobile renders a dark background but keeps dark text (unreadable)
  until a refresh, which lands in light mode. Policy decision (Frosty
  Cloud): the site should ALWAYS default to light mode; dark mode only
  when the visitor explicitly toggles it; the chosen mode must persist
  across pages and refreshes (stored client-side, e.g. localStorage)
  and never flip on its own.
- **B3 — Mobile: footer social icons stack vertically** (Frosty Cloud
  observation) despite ample horizontal space. Root cause identified:
  the mobile stylesheet's vertical stacking of `.social-links` targets
  the open header menu but the footer shares the class.
- **B4 — Publish not visible without hard refresh** (client issue 4).
  Self-resolved on hard refresh; consistent with browsers still
  holding pages cached before the `_headers` fix shipped at cutover.
  Expected to disappear on its own; monitor rather than fix.

## Scope: CMS usability issues

- **C1 — Folders for uploaded images** (client issue 1). The installed
  media browser organizes by TAGS, not folders — the client looked for
  folder creation and found nothing. Options: (a) train tags as the
  organizing tool (works today: select images → add a tag → filter by
  tag when picking); (b) evaluate Sanity's newer first-class Media
  Library product (real folders/collections) and adopt if available on
  the current plan.
- **C2 — Bulk-delete uploaded images** (client issue 2). She uploaded
  some wrong pictures and couldn't multi-select to delete. The media
  plugin is believed to support checkbox multi-select + delete —
  verify and document the steps, or find the gap.
- **C3 — Adding photos to a post one at a time** (client issue 3). She
  is using the "Add item" button, which is inherently one-at-a-time.
  The schema was deliberately shaped (array of image) so that dragging
  MULTIPLE files from the computer onto the Photos field creates one
  item per file. Verify this works in the deployed Studio, and teach
  the drag path; also verify whether the media picker supports
  multi-select insert into an array.
- **C4 — Cancel individual files during a batch upload** (client
  request, Google Drive-style X-per-file). Verify what Sanity's
  uploader offers; document or note the limitation.
- **C5 — Editing/removing photos on pre-existing (demo) posts.**
  Early in the session the photo list didn't show for a demo post;
  later she successfully edited and replaced content. Verify demo
  posts are fully editable (suspected UI confusion with collapsed
  items rather than a data problem).
- **C6 — Thumbnail crop/centering ("cover selection", client issue
  5).** She wants to control which part of a photo shows in the
  auto-cropped grid thumbnail (e.g. shift right to show two people).
  Sanity images already carry a crop/hotspot editor in the Studio
  (the crop icon on any image field — available to her today). The
  missing half: the site currently center-crops via CSS and ignores
  the hotspot. The site must request hotspot-aware cropped derivatives
  so her chosen focal point drives every thumbnail.

## Technical details

- **B1/B3 (CSS):** scope the mobile `.social-links` vertical stacking
  to the header (`.site-head .social-links`) or add a
  `.site-foot .social-links { flex-direction: row }` override in the
  mobile media query; header overlap fix in `layout.css` mobile rules
  (`.nav-burger` / `.site-head-center` positioning at ≤850px).
- **B2 (theme):** the current theme script follows
  `prefers-color-scheme` on first paint but the body text custom
  properties don't flip until re-init — hence dark background/dark
  text. Change in `Layout.astro`'s inline theme script: initial theme
  = localStorage value if set, else LIGHT (ignore system preference);
  toggle writes localStorage; no flash via inline pre-hydration
  script. This also satisfies "retain mode on refresh."
- **C6 (hotspot rendering):** photos already store crop/hotspot
  (`options.hotspot: true` since the schema was built). In
  `src/lib/sanity.ts`, tile/thumb builders gain fixed aspect crops:
  e.g. cards `.width(1200).height(900).fit('crop')` — the image CDN
  automatically honors each image's hotspot/crop when both dimensions
  are set. PostCard switches from CSS `background-size: cover` on an
  uncropped image to the cropped derivative (visual result identical
  for centered hotspots, correct for adjusted ones).
- **C1–C5:** verification pass against the deployed Studio (браuser
  automation, cost-estimated separately per protocol) plus plugin
  docs; outcomes written back into this doc.
- **F1/F2 (article layout):** schema: add `layout` string field
  (`gallery` default | `article`) to portfolioPost, and an
  `articleBody` portable-text type extending blockContent with an
  `imageRow` object (array of 1–2 images, rendered as the two-column
  tile row from the reference site). Site: Work.astro branches on
  `layout`; article mode renders PortableText with a custom imageRow
  component; all rendered images keep the existing lightbox behavior
  (delegated click handler + the existing lightbox markup). About page
  (`page` type) gains the same `articleBody` capability. Gallery mode
  remains untouched for existing posts (default), so nothing she has
  built changes without her opting in per post.
- **A1 (API):** role change via the project ACL endpoint; member
  removal via the members endpoint — both one-call operations with the
  existing CLI token.

## Phase 1 & 2 outcomes (appended July 23, 2026)

**Phase 1 — shipped to production (commit 18053ad):** B1 (logo
clearance), B2 (always-light default + explicit-toggle persistence +
opt-out of Chrome-for-Android Auto Dark Theme, which was force-
darkening pages with un-inverted text), B3 (footer icons horizontal
on mobile), C6 site half (grid/tile thumbnails now request
hotspot-centered crops — the Studio crop tool controls thumbnails).

**Phase 2 — verification results:**

- **C1 (folders): folders are NOT available on the current plan.**
  Sanity's real folder system ("Media Library" with collections) is
  an Enterprise add-on. The installed free plugin organizes by TAGS —
  there is no missed setting. Workflow to teach: Media tab → select
  image(s) → add/create a tag in the side panel (bulk-taggable) →
  filter by tag when picking images. Tag names can mirror her mental
  folders ("Maternity 2026", "Posters", …).
- **C2 (bulk delete): YES.** The media browser supports selecting
  multiple assets and deleting in bulk. Caveat: the deletion is one
  transaction — if ANY selected asset is still used by a post, the
  whole delete fails. Use the plugin's "in use" filter facet to
  select only unused assets first.
- **C3 (add many photos to a post): two confirmed paths.**
  (a) Media tab supports batch drag-and-drop uploads into the global
  library (documented). (b) Into a post directly: drag multiple files
  from the computer ONTO the Photos field — one live confirmation
  still pending (30-second test): select several files in
  Finder, drag onto the Photos box, expect one entry per file. The
  media picker's multi-select insert into arrays is NOT documented —
  assume single-insert there.
- **C4 (cancel per-file during upload): not documented** in the
  plugin; assume unavailable. Practical mitigation: wrong uploads are
  cheap to fix via C2 bulk delete.
- **C5 (editing demo posts): RESOLVED with proof.** API check shows
  the demo posts' photo arrays are fully keyed/editable — and the
  client has in fact edited them (First Smiles title changed, photos
  13 → 7). The early hiccup was collapsed-item UI confusion.
